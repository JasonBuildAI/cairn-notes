## 这门课要解决什么问题

一个 AI 应用要让模型“真的做事”，至少要回答四个问题：

```text
1. 代码在哪里跑，才不会伤到宿主机？
2. 跑起来之后，命令、文件、输出怎样被可靠地收集？
3. 它怎样联网、怎样拿凭据，而不把数据或密钥送出去？
4. 当模型自己决定下一步时，谁保证它不失控、成本可控、事后可查？
```

OpenSandbox 用一套分层设计回答这四个问题。这门课沿着**一次沙箱任务的生命周期**，把这套设计拆开、跑通、再合起来。

## 一条主线

```text
创建意图
  -> 控制面受理（认证、TTL、状态）
    -> 运行时落地（容器 / Pod / 微虚拟机）
      -> 端点解析（地址不是猜的）
        -> 执行（execd：命令、文件、流）
          -> 网络与凭据（该通的通，该断的断）
            -> 证据回流（退出码、stderr、产物）
              -> TTL / 暂停 / 销毁
```

每一阶段只回答这条链上的一个岔路口。阶段之间不是“知识点堆叠”，而是**同一个任务在不同层上的展开**。

## 怎么学：五步循环

每一章都走同一个循环，不跳步：

```text
1. 提问：如果我是设计者，我会怎么解决？
2. 画图：把这一层的输入、输出、失败点画出来
3. 读码：只读能回答问题的文件，不做无目的通读
4. 实验：跑一个最小验证，记录成功与失败两种形态
5. 复述：不看资料讲回来，并说出两个边界
```

判断“学会了”的标准不是“跑通了”，而是：**能解释为什么这样设计，能指出它在什么条件下失效。**

## 八个部件

不管目录怎么变，任何 AI 执行平台都要回答这八件事：

| 部件 | 要回答的问题 | OpenSandbox 中的对应 | 阶段 |
| --- | --- | --- | --- |
| 入口 | 人和程序通过什么使用平台？ | Python/JS/Go/Kotlin/C# SDK、`osb` CLI、MCP | 6 |
| 契约 | 客户端为什么不被某个后端锁死？ | `specs/` 下的 OpenAPI | 1、6 |
| 生命周期 | 环境何时创建、过期、销毁？ | `server/` 控制面 | 2 |
| 运行时 | 环境跑在容器、Pod 还是微虚拟机？ | Docker、Kubernetes、FastSandbox | 4 |
| 执行 | 模型动作怎样真正发生？ | `components/execd/` | 3 |
| 网络 | 流量怎样进入、出去、被限制？ | endpoint、ingress、egress | 5 |
| 安全 | 不可信代码和密钥怎样被约束？ | 隔离运行时、资源限制、网络策略、Vault、租户 | 4、5、8 |
| 工程 | 怎样证明可靠、可观测、可演进？ | 测试、诊断、指标、发布验证 | 8 |

一句话串起来：**入口发起，契约约束，控制面安排，运行时落地，数据面执行，网络面治理，安全面兜底，工程面证明。**

## 三条纵线

每一章都会反复出现这三条线，不要把它们当“附录”：

| 纵线 | 问题 | 典型落点 |
| --- | --- | --- |
| 证据流 | 这个结论凭什么可信？ | exit_code、stderr、文件、conditions、日志、trace |
| 信任边界 | 谁不可信？密钥在哪？ | 沙箱内容、egress、Credential Vault、租户隔离 |
| 能力条件 | “支持”需要什么前提？ | runtime、配置、版本、镜像、Pool/模板约束 |

## 环境提醒

- 阶段 0–3 需要可用的 Docker daemon；Windows 上使用 Docker Desktop + Linux 容器（依赖 WSL2）。
- 服务端与示例主要使用 Python 3.10+；其他语言 SDK 需要对应工具链。
- Kubernetes、FastSandbox、Pool、快照、Credential Vault 都有后端与配置前置条件，不能把“接口存在”当成“当前环境可用”。
- **作者编写这套笔记时没有安装 Helm，Docker daemon 也未运行**，因此 Kubernetes 部署、Pool、快照等实验未实际执行；文中已逐处标注“需集群/未验证”。阅读时请把“命令存在”和“本机已验证”分开。
- 教材基于 1.1.1 源码与官方文档交叉校对；实际运行以当前配置和后端能力为准。

## 学习契约

读完不等于学会。每个阶段结束时，至少做到：

- 不看资料讲清该模块解决什么问题、边界在哪。
- 能画出一次调用的时序图，并指出失败点。
- 能写出最小可运行示例，或给出有依据的伪代码。
- 能说出两个常见误用及其后果。
- 能诚实标注“我验证了什么、没验证什么”。

最终要同时具备四种能力：**把模型能力产品化、把工具边界工程化、把风险治理显式化、把系统行为可观测化。** OpenSandbox 是训练这四种能力的一个高质量样本。
