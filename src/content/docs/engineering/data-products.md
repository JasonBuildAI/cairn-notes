---
title: 指标、实验与数据治理
description: 从埋点到 A/B 测试，理解怎样用数据判断 AI 产品是否真的变好。
---

“日志里看起来很多”不等于产品有效。数据要从采集开始就有明确含义，之后才可能得到可信的指标、实验和 AI 评测。

## 1. 先把事件定义清楚

一个可用的埋点至少包含：

| 字段 | 作用 | 例子 |
| --- | --- | --- |
| 事件名 | 稳定、可读的语义 | `chat_message_sent` |
| 时间 | 客户端与服务端时间 | 同时保留以便对齐 |
| 用户 / 会话 | 去重与串联 | 匿名 ID、登录 ID、session ID |
| 属性 | 业务上下文 | 模型、入口、工具名、耗时 |
| 版本 | 解释口径变化 | schema 版本、应用版本 |
| 幂等键 | 避免重复计数 | event ID |

事件名和属性要有字典，避免今天叫 `chat_send`、下周叫 `send_message`。版本字段也很重要：同一指标在应用升级后口径变了，如果不记录，趋势图会出现无法解释的跳变。

采集位置也要分清：客户端埋点适合点击与曝光，但可能被拦截或重复上报；服务端埋点更适合支付、模型调用等事实。敏感文本尽量不采集，必须采集时做最小化、脱敏和保留期限。

## 2. 指标先有定义，再有图表

同一句“平均响应时间提高了”可能至少有三种算法：所有请求平均、成功请求平均、按用户先平均再平均。要让指标可信，需要写清楚：

- 分子、分母和时间窗口是什么。
- 哪些请求被排除，失败请求算不算。
- 按用户、会话还是请求计数。
- 数据延迟多久，何时可以认为完整。

均值容易被极端值拉动；中位数更能代表典型请求。标准差描述波动，但分布偏斜时还应看分位数，例如 P50、P95、P99。

分析通常从“拆分、计算、组合”开始：按模型、入口、版本或用户群分组，再计算转化率和耗时。聚合能揭示群体规律，却也可能掩盖某个小群体一直失败。

## 3. 漏斗和留存回答不同问题

**漏斗**描述一组有序步骤的转化：

```text
打开页面 → 发起提问 → 收到回答
         → 复制 / 采纳 → 再次使用
```

每一步都要定义事件、去重方式和允许的时间范围，否则“转化率”只是自定义数字。

**留存**描述用户是否回来。常见口径是日留存、周留存和滚动窗口。不同窗口不可直接比较，分母也应该排除没有机会再次使用的用户。留存曲线可以辅助判断产品是否形成稳定价值，但不能单独证明因果。

## 4. A/B 测试不是把流量随便分两半

一个可信实验至少要有：

1. 明确假设：改什么，预期哪个指标变化，为什么。
2. 稳定的随机分流：同一用户尽量落在同一组。
3. 足够的样本和预先计算的时长。
4. 主指标，以及防止体验恶化的护栏指标。
5. 实验前写好的分析方案，避免看到显著结果才改口径。

常见陷阱包括样本不足、提前偷看数据、同时比较太多指标、实验期间上线其他变化，以及“新奇效应”导致短期结果不能代表长期影响。

AI 功能还要额外关注成本和风险：成功率提升时，token 成本是否暴涨？用户更快得到答案时，引用正确率是否下降？安全拒答增加时，正常请求是否被误伤？

## 5. 图表要让结论可检查

| 要回答的问题 | 优先图表 | 注意点 |
| --- | --- | --- |
| 随时间怎样变化 | 折线图 | 时间间隔一致，标出版本与事件 |
| 类别之间谁大 | 条形图 | 从零开始，保持排序有含义 |
| 构成比例 | 堆叠条或饼图 | 类别不要过多，合计必须清楚 |
| 分布与尾部 | 直方图、分位数图 | 不要只用均值 |
| 两变量关系 | 散点图 | 相关不等于因果 |

截断坐标轴、3D 饼图、颜色过多和双 Y 轴都可能放大或隐藏差异。图表标题应直接说明结论和范围，而不是只写“数据总览”。

## 6. 数据治理是让指标可追溯

数据质量通常从完整性、准确性、一致性、及时性、唯一性和有效性检查。治理不只是清洗脏数据，还包括：

- 指标与字段的负责人和定义；
- 数据血缘：一张报表依赖哪些表、任务和上游事件；
- 元数据：字段含义、类型、敏感级别和更新时间；
- 访问权限、脱敏、审计和保留期限；
- 常见分层：原始层 ODS、明细层 DWD、汇总层 DWS、应用层 ADS。

分层的目的不是堆名字，而是隔离原始变化、复用清洗逻辑，并让报表口径能被追到源头。每一层都应明确粒度和主键，否则后续聚合很容易重复计数。

## 7. 把评测和 trace 当作数据产品

AI 系统的“质量数据”至少要保存：

| 数据 | 用途 |
| --- | --- |
| 固定评测集 | 回归比较，不随线上数据漂移 |
| 人工标注 | 判断正确性、引用、风格与安全 |
| 线上 trace | 还原模型、工具、耗时、token 和错误 |
| 用户反馈 | 发现真实失败，但不等于总体质量 |
| 运行版本 | 关联模型、提示词、工具和检索索引 |

评测集要有版本和来源说明，避免训练数据或提示词无意中泄漏答案。线上失败样本可以进入候选集，但先脱敏、去重并由人确认结论，再用于回归。

对 Agent 来说，最终回答正确不代表过程安全：工具是否越权、是否重复调用、是否超出预算、是否泄露敏感信息，都应作为独立指标记录。

## 8. 一页检查表

1. 每个指标是否有唯一、可复现的定义？
2. 埋点是否区分客户端、服务端和幂等重试？
3. 实验是否预先定义主指标、样本与停止条件？
4. 图表是否忠实表达分布、范围和不确定性？
5. 数据能否追到来源，敏感字段是否被限制？
6. AI 质量是否有固定评测集、在线 trace 和回归记录？
