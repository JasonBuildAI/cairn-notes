description: DNS、TLS、反向代理、IAM 与对象存储，以及 AI 系统真正需要守住的边界。

一个请求从浏览器到模型服务，会经过多个信任边界。看懂这些边界，比背云厂商产品名更重要。

## 1. 请求怎样到达服务

```
用户
 │
 ├─ DNS：域名解析到入口地址
 ├─ TLS：验证服务器身份并建立加密连接
 ├─ 反向代理 / 负载均衡 / 网关
 │      ├─ 路由、限流、鉴权、日志
 │      └─ 转发到服务实例
 ├─ 应用服务
 │      ├─ 模型 API / 推理运行时
 │      ├─ 数据库 / 对象存储
 │      └─ 密钥服务
 └─ 响应（可能以流式返回）
```

在每一段问三个问题：谁验证身份？谁限制访问？失败时留下什么证据？

## 2. DNS 与 HTTPS

| 记录 | 用途 |
| --- | --- |
| `A` / `AAAA` | 域名指向 IPv4 / IPv6 地址 |
| `CNAME` | 域名指向另一个域名 |
| `TXT` | 所有权验证、邮件策略等文本记录 |

TTL 决定缓存多久。修改记录后，旧值可能仍被递归解析器缓存，所以“本机能解析”不等于“全世界立即生效”。

TLS 握手可以压缩成四步：

| 步骤 | 发生什么 |
| --- | --- |
| 1. ClientHello | 客户端说明支持的协议、加密算法和域名 |
| 2. ServerHello + 证书 | 服务器选择参数，返回证书链 |
| 3. 验证 | 客户端检查域名、有效期、签名和信任链 |
| 4. 密钥协商 | 双方建立会话密钥，之后的 HTTP 被加密 |

证书过期、域名不匹配和中间证书缺失，都会表现为“连接失败”，而不是应用日志里的业务错误。证书续期和到期告警应自动完成。

## 3. 反向代理、负载均衡与 API 网关

| 组件 | 主要职责 |
| --- | --- |
| 反向代理 | 接收外部请求，转发给内部服务，处理静态文件和缓存 |
| 负载均衡 | 在多个实例间分配流量，做健康检查和故障摘除 |
| API 网关 | 在入口统一鉴权、限流、路由、审计和协议转换 |

它们可以合并部署，也可以分层部署。不要因为使用了网关，就假设后端服务不需要权限检查；纵深防御比单点信任可靠。

## 4. 云资源的最小模型

| 资源 | 典型用途 | 注意点 |
| --- | --- | --- |
| 计算实例 / 容器服务 | 运行应用 | 区域、规格、磁盘、伸缩 |
| 对象存储 | 文件、日志、模型产物 | 桶策略、加密、生命周期 |
| CDN | 缓存静态资源 | 缓存键、回源、失效策略 |
| 托管数据库 | 持久化业务数据 | 备份、连接数、网络边界 |
| 密钥服务 | 保存 API Key | 权限、轮换、审计 |

对象存储不是本地磁盘。上传、下载、预签名 URL、权限和生命周期都要显式设计。CDN 也不能缓存带用户身份的响应。

## 5. IAM：默认拒绝

身份与访问管理（IAM）解决“谁可以对什么资源做什么”。最低权限原则意味着：

- 每个服务使用独立身份，不共用一把万能管理员密钥。
- 权限绑定到具体资源与动作，而不是整个账号。
- 临时凭据优先于长期 Access Key。
- CI/CD、开发者和线上运行时使用不同权限。
- 权限变更和密钥使用有审计记录。

密码和密钥不要出现在代码、镜像、提示词、截图或日志里。生产环境通过环境变量或密钥服务注入，并准备轮换方案。

## 6. 基础设施即代码

IaC 把网络、计算、存储和权限写成可审查的声明文件，再由工具计算变更。

```text
配置 → plan → 人工审查 → apply → 资源
                    └→ 状态漂移检查 / 回滚
```

关键不是“用了某个工具”，而是变更可审查、可重复、可追踪。手动改控制台会制造漂移；IaC 状态文件也可能包含敏感信息，不能随便公开。

## 7. AI 系统要守住的边界

| 边界 | 风险 | 基本措施 |
| --- | --- | --- |
| 用户输入 | 注入、超长、恶意文件 | 校验、限额、隔离 |
| 模型输出 | 误导、危险命令、伪造 JSON | 结构化校验、人工/策略确认 |
| 工具调用 | 越权读写、外发数据 | 最小权限、参数白名单、审计 |
| 代码执行 | 逃逸、资源耗尽 | 沙箱、超时、资源限制、网络策略 |
| 密钥 | 被提示词或日志带出 | 不进入上下文、短期凭据、输出过滤 |
| 出口网络 | 数据外泄、访问内网 | 默认拒绝、域名/IP 允许清单 |

提示词不能替代权限系统。模型被要求“不要泄露密钥”并不等于技术上无法访问；真正的保障是它根本拿不到不该有的权限。
