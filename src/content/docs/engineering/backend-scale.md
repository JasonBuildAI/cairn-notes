---
title: 并发、缓存与异步
description: 后端在用户等待之外还要处理并发、排队、缓存、重试和过载。
---

一个请求变慢时，问题可能不在业务代码，而在排队、锁、缓存未命中、下游限流或任务积压。这一页把常见的“系统变慢”拆成可检查的部件。

## 1. 并发不是同时跑得越多越好

| 模型 | 典型表现 | 主要风险 |
| --- | --- | --- |
| 线程 / 进程池 | 每个任务占用执行单元 | 上下文切换、内存和连接数 |
| 事件循环 | 单线程处理大量 I/O | 一段同步代码阻塞所有请求 |
| 协程 / goroutine | 轻量任务并发 | 共享状态和取消传播 |
| 消息消费者 | 按队列并发消费 | 重复、乱序和积压 |

并发提高吞吐，但会增加内存、锁竞争和下游压力。连接池、线程池、模型并发都有上限；上限不是越大越好，超过下游容量只会把等待转移到别处。

## 2. 延迟、吞吐和排队

- **延迟**：一次请求从进入到返回经历多久。
- **吞吐**：单位时间完成多少请求。
- **排队**：到达速度持续超过处理速度时，等待时间会快速上升。

平均值会掩盖问题。用户经常感受到的是 p95、p99 和长尾请求；一个慢模型调用可能占住连接和上下文很久。设置超时、限制单请求 token、拆分长任务，通常比单纯增加实例更有效。

## 3. 缓存要回答四个问题

1. **缓存什么**：对象、查询结果、页面片段还是模型响应？
2. **key 是什么**：是否包含用户、租户、权限、版本和模型参数？
3. **什么时候失效**：TTL、主动删除、版本号还是事件驱动？
4. **失效时怎样降级**：回源、排队、返回旧值还是报错？

| 层级 | 例子 | 注意 |
| --- | --- | --- |
| 浏览器 / CDN | 静态资源、公开页面 | 不要把用户私有内容缓存给所有人 |
| 应用内存 | 热配置、小型映射 | 多实例之间可能不一致 |
| 分布式缓存 | Redis 等 | 序列化、过期、穿透和雪崩 |
| 数据库 | 查询缓存、物化视图 | 更新成本和一致性 |

常见故障也有固定名字，知道名字才能快速选对防线：

| 现象 | 发生什么 | 常见处理 |
| --- | --- | --- |
| 缓存穿透 | 查询根本不存在的数据，缓存和数据库都反复落空 | 参数校验、空值短期缓存、入口限流 |
| 缓存击穿 | 一个热点 key 失效，大量请求同时回源 | 单飞/互斥重建、逻辑过期、提前刷新 |
| 缓存雪崩 | 大批 key 同时失效，或缓存整体不可用 | TTL 加随机抖动、多级缓存、熔断和降级 |

权限相关的缓存必须把授权范围放进 key，或者先查权限再取内容。模型响应缓存要包含模型、参数、提示模板和上下文摘要，否则会把错误结果复用给不同场景。

## 4. 消息队列和任务队列

消息队列解决解耦和削峰，任务队列强调“稍后执行某个工作”。两者都可能出现重复投递，所以消费者要幂等。

```
生产者 ──► 队列 ──► 消费者
                   ├─ 成功：确认
                   ├─ 重试：退避
                   └─ 失败：死信 / 人工
```

至少要确定：投递语义、顺序要求、重试上限、死信策略、可见性超时和监控指标。不要把一个需要立即返回给用户的操作随意异步化；用户要看到结果时，异步只适合“已接受，稍后完成”的产品语义。

## 5. 限流、背压和熔断

| 机制 | 解决的问题 |
| --- | --- |
| 限流 | 限制单位时间请求数，保护自己和上游 |
| 背压 | 下游处理不过来时，向上游传递减速信号 |
| 熔断 | 下游持续失败时暂时停止调用，避免拖垮全站 |
| 降级 | 关闭非核心能力，保留主流程 |
| 重试 | 对偶发失败再试，但必须有上限和退避 |

限流按用户、租户、API key 或全局维度设计。返回 429 时告诉客户端何时可以重试；对模型 API 还要区分限流、超时和内容错误。

常见限流算法：

| 算法 | 思路 | 特点 |
| --- | --- | --- |
| 固定窗口 | 每个时间窗计数 | 简单，但窗口边界可能放过两倍流量 |
| 滑动窗口 | 按最近一段时间计数 | 更平滑，状态和计算成本更高 |
| 令牌桶 | 按速率补充令牌，请求消耗令牌 | 允许有限突发，适合 API 配额 |
| 漏桶 | 请求进入队列，以固定速率流出 | 输出平滑，但排队增加延迟 |

多实例服务需要共享计数或使用网关统一限流，否则每个副本单独计数会把总配额放大。

## 6. 搜索和文件不要硬塞进主库

全文搜索通常需要倒排索引，而不是对数据库做 `LIKE '%关键词%'`。搜索引擎适合相关性排序、分词和聚合，但索引是另一份数据，需要考虑同步、延迟、重建和权限过滤。

文件、图片、模型权重和导出包通常放对象存储，数据库保存元数据和访问策略。上传使用预签名 URL，下载要校验授权；本地磁盘不适合做多实例共享存储。

## 7. AI 场景的额外判断

- 批量 embedding、文档解析、评测和报告生成适合任务队列。
- 用户等待的流式回答要限制队列时间和最大生成长度。
- 工具调用要设置超时、最大步数和幂等键。
- 缓存要区分“公开事实”和“带用户上下文的结果”。
- 上游模型限流时，排队、降级和错误提示都属于产品能力。
