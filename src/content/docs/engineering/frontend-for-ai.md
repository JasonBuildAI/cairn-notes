description: 框架、状态、流式通信、性能和可访问性，怎样落到一个 AI 聊天界面上。
---

前端工程的核心不是选哪个框架，而是把“用户动作 → 请求 → 增量响应 → 可恢复的界面状态”组织清楚。AI 应用多了流、取消、重试和不完整结果，这几件事会被放大。

## 1. 框架只是组织方式

React、Vue、Svelte 都在解决组件化、状态更新和视图同步。差异主要在更新模型、生态和团队熟悉度，不会替你决定数据边界。

选择时先回答：

- 页面是否真的有大量交互，还是静态内容为主？
- 是否需要服务端渲染、路由和搜索？
- 团队能否维护这套工具链？
- 流式输出、取消和错误恢复准备放在哪一层？

小型内部工具用最小方案往往更稳。不要为了“看起来现代”引入一整套状态管理和微前端。

## 2. 路由、构建与项目结构

**路由。** 现代前端用 History API 改 URL 而不整页刷新，但刷新深链接时服务器必须把未知路径回退到应用入口。URL 要能表达“当前在哪个会话、哪个筛选条件”，这样刷新、分享和后退才可靠；不要把令牌、完整提示词或敏感数据放进 URL。前端路由守卫只改善体验，真正的权限检查必须在服务端。

**构建。** TypeScript、JSX、CSS 预处理器和新语法通常要经过转译、打包或按路由拆包，才能交给浏览器。产物文件名带内容哈希，适合长期缓存；Source Map 帮助定位压缩后的错误，但不要无条件公开包含源码的内容。开发服务器的代理规则不能当成生产网关，CORS、CSP、缓存和超时仍要在真实入口验证。

**结构。** 小项目按页面分目录即可。变大后按业务功能组织，例如把会话、上传、评测各自放在一个 feature 内，再共享 API 客户端、通用组件和工具函数。请求层集中处理鉴权、错误和取消，避免每个组件各写一套 `fetch`。目录名字不是重点，重点是边界：谁可以依赖谁、共享状态放在哪里、删除一个功能要动多少文件。

## 3. 状态要分层

| 状态 | 例子 | 放在哪里 |
| --- | --- | --- |
| 服务端状态 | 会话列表、历史消息 | 请求层 + 缓存，避免到处复制 |
| 会话状态 | 当前选中会话、草稿、附件 | 页面级或局部 store |
| 流状态 | 已生成文本、是否在生成、能否取消 | 与请求生命周期绑定 |
| UI 状态 | 弹窗、选中项、滚动位置 | 尽量靠近使用它的组件 |
| 错误状态 | 限流、超时、鉴权失败、部分失败 | 明确分类，不用一句“出错了”覆盖 |

一个常见错误是把所有东西塞进全局 store。全局状态越多，清理和并发就越难。

```
用户输入 → 组装请求 → 发送 / 取消
             ├→ 增量块：更新流状态 / 渲染
             ├→ 错误：保留内容 / 分类 / 重试
             └→ 完成：固化为消息 / 记录用量
```

## 4. 选对实时通信方式

| 方式 | 方向 | 适合 | 代价 |
| --- | --- | --- | --- |
| 普通 HTTP | 请求 → 响应 | 一次性生成、普通 CRUD | 不适合持续增量 |
| HTTP 流 / SSE | 服务端 → 客户端 | 文本 token、进度、事件 | 需要处理分块、断开和重连 |
| WebSocket | 双向 | 协作、语音、双向控制 | 连接管理、代理和心跳更复杂 |
| 长轮询 | 近似推送 | 兼容性优先 | 延迟和连接开销更高 |

SSE 的典型消息长这样：

```text
event: token
data: {"text":"你"}

event: token
data: {"text":"好"}

event: done
data: {"finishReason":"stop"}
```

解析时先累积缓冲区，再按协议分隔符切事件。不要假设每次 `read()` 都正好拿到一条完整 JSON。断线重连要能从最后确认的位置继续，或者明确告诉用户“这段需要重试”。

## 5. 流式界面的性能

- 不要每个 token 都触发整棵消息树重渲染。按一帧或一个小时间窗合并更新。
- 已完成消息和正在生成消息分开处理，避免历史消息反复计算。
- 长会话使用虚拟列表，但要处理动态高度和滚动锚点。
- 用户向上查看历史时，不要强行拉回底部。
- 用 Performance 面板量输入延迟、长任务和 layout shift，而不是只测试本地空会话。

指标优先看用户能感受到的东西：首次内容出现时间、输入是否卡顿、滚动是否稳定、完成后能否继续操作。

## 6. 可访问性、国际化与安全

**可访问性。** 生成中的状态用合适的 `aria-live` 区域提示，但不要逐 token 朗读；完成时再播报结果。取消、重试、复制、发送都要能用键盘操作，焦点在对话框和页面之间移动时要可预测。

**国际化。** 文案不要拼句子；日期、数字和复数交给 `Intl`。中文、英文和阿拉伯语的长度、方向不同，布局要留出伸缩空间。

**安全。** CORS 不是鉴权。不要把长期密钥放进浏览器代码或 localStorage。Markdown 渲染做 HTML 白名单清洗，服务端校验权限，给流式接口设置鉴权、限流和超时。模型输出不能直接当 SQL、shell 或工具参数执行。

## 7. 上线前一页检查

1. 生成中、完成、取消、失败四种状态都能恢复。
2. 断网、限流、超时有不同提示，不会吞掉已生成内容。
3. 多标签页和重复点击不会产生重复业务动作。
4. 长会话滚动与输入仍然流畅。
5. 键盘操作、屏幕阅读器和缩小窗口都能用。
6. 日志不记录敏感 prompt 和明文凭据。
