---
title: 可复现的开发环境
description: 从 PATH、依赖、端口到 SSH，把“在我机器上能跑”变成可检查的环境契约。
---

“环境问题”通常不是某个神秘配置，而是几条契约没有写清楚：系统、运行时、依赖、端口、凭据和外部服务。能把这些列出来，问题就从玄学变成了检查表。

## 1. 环境是一份契约

| 项目 | 要固定什么 | 常见故障 |
| --- | --- | --- |
| 系统 | macOS / Linux / Windows，CPU 架构 | 二进制只能在一个平台运行 |
| 运行时 | Node、Python、JVM、CUDA 版本 | 本机可用，CI 或服务器失败 |
| 依赖 | lockfile、虚拟环境、镜像版本 | 今天安装的版本和昨天不同 |
| 配置 | 环境变量、配置文件、默认值 | 缺少一项就启动失败 |
| 网络 | 端口、代理、DNS、防火墙 | 进程在运行，但请求到不了 |
| 外部服务 | 模型 API、数据库、对象存储 | 本地正常，上线缺少权限 |

“可复现”最低要求是：换一台干净机器，照着仓库里的说明能找到版本、装上依赖、启动服务并验证一次请求。

## 2. 命令找不到，多半是 PATH

Shell 根据 `PATH` 从左到右找可执行文件。同名程序装了多个版本时，路径顺序会决定实际运行的是哪一个。

```bash
# macOS / Linux
which node
node --version
printenv PATH

# Windows PowerShell
Get-Command node
node --version
$env:PATH
```

排查顺序：命令是否安装 → 所在目录是否在 `PATH` → 当前终端是否重新打开 → 项目是否要求另一个版本。不要靠修改全局环境解决所有问题；项目级版本文件、虚拟环境或容器通常更可控。

## 3. 依赖要可重建，而不是可复制

| 场景 | 推荐做法 | 不该做什么 |
| --- | --- | --- |
| Node | 提交 lockfile，使用项目内依赖 | 把 `node_modules` 当源码提交 |
| Python | 每个项目独立虚拟环境，锁定依赖 | 所有项目共用一个全局环境 |
| 容器 | 固定基础镜像，复制 lockfile 后安装 | 每次构建都拉最新版 |
| 模型调用 | 固定模型名、参数和 API 版本 | 把临时模型别名写死在业务里 |

```bash
python -m venv .venv
npm ci
```

`npm ci` 会按 lockfile 精确安装；它和 `npm install` 的语义不同。生产构建更关心“可重复”，而不是“拿到最新”。

## 4. Shell：把命令组合成可检查的流程

终端是窗口，Shell 才是解释命令的程序。日常不需要背完整语法，但要知道下面这些动作：

| 动作 | 例子 | 作用 |
| --- | --- | --- |
| 当前目录 | `pwd`、`cd`、`ls` | 命令作用于哪里 |
| 参数 | `rg "timeout" src` | 把输入交给程序 |
| 管道 | `git diff \| less` | 前一个命令的输出变成后一个的输入 |
| 重定向 | `python job.py > out.log 2>&1` | 分别保存标准输出和错误输出 |
| 退出码 | `echo $?` | `0` 通常表示成功，非零表示某类失败 |
| 串接 | `npm ci && npm test` | 前一步成功才执行下一步 |
| 中断 | `Ctrl+C` | 给前台进程发送中断信号 |

Shell 脚本至少要处理变量、引号和失败。下面这种写法比把命令堆在一个字符串里可靠：

```bash
set -euo pipefail
input="${1:?missing input file}"
python -m json.tool "$input" > /dev/null
```

变量必须加引号，避免空格和通配符被二次解释；不要把用户输入拼进 `eval`、`sh -c` 或数据库命令。Windows PowerShell 的命令名、环境变量和引号规则不同（例如 `$env:PATH`），不能把 Bash 脚本原样复制过来。

## 5. IDE 与正则：减少重复检查

IDE 不是“功能更多的记事本”。真正值得依赖的能力是：语言服务给出的跳转、补全和类型错误，断点调试，集成终端，任务运行，以及 Git 差异查看。

编辑器配置应服务于项目，而不是把关键步骤藏在个人设置里。格式化、lint、类型检查和测试要能在命令行或 CI 重复运行；`.vscode/` 中的个人界面设置不要默认提交。打开陌生仓库时，先确认项目根目录和任务脚本，再决定是否信任并执行。

正则适合在**边界清楚、长度有限**的文本里抽取或校验：

```text
^\d{4}-\d{2}-\d{2}$   # 日期形状
(?i)error:\s+(?<code>[A-Z_]+)
# 从日志里抓错误码
```

- `^`、`$` 锚定整行；`[]` 是字符集合；`()` 分组；`|` 表示选择。
- `*`、`+`、`?` 控制重复；`.*?` 是非贪婪匹配。
- 命名分组比按位置取第几个括号更容易维护。
- 不要用正则解析 HTML、JSON、SQL 或复杂语法，使用对应解析器。
- 真实输入可能很长，避免灾难性回溯；设置长度上限，准备超时或替代方案。

邮箱、URL 和信用卡号也不要仅靠一条“万能正则”证明有效。正则能检查形状，最终仍要由业务规则、解析器或外部系统确认。

## 6. 端口和 localhost

```
编辑器 / 浏览器
      │
      ▼
  shell 启动进程 ──► 监听 127.0.0.1:8000
      │                    │
      └── 环境变量/密钥 ───┘
                           │
                    curl / 浏览器请求
```

`127.0.0.1` 只接受本机连接；`0.0.0.0` 表示监听所有网卡。开发服务默认只绑定本机，需要对外访问时再经过反向代理、防火墙和鉴权。端口被占用时，先查是谁在监听，不要反复换端口掩盖问题：

```bash
ss -ltnp | grep 8000        # Linux
netstat -ano | findstr 8000 # Windows
```

## 7. SSH 是信任关系，不是登录口令

SSH 密钥通常成对存在：私钥只留在自己的设备，公钥放到目标机器或 GitHub。私钥不要进仓库，也不要通过聊天工具发送。

```bash
ssh-keygen -t ed25519 -C "device-name"
ssh -T git@github.com
```

第一次连接会记录主机指纹。指纹突然变化时先停下核对，而不是直接删掉 `known_hosts`。给自动化流程使用独立密钥，并只授予它需要的仓库或主机权限。

## 8. AI 服务的最小自检

启动后按顺序验证，不要把“进程没退出”当成“服务可用”：

1. 进程监听在预期地址和端口。
2. 健康检查返回稳定状态码。
3. 不调用模型也能走通最小请求。
4. 密钥从环境变量或密钥服务读取，日志里没有明文。
5. 模型超时、限流和无效响应都有明确错误。
6. 失败请求带有可检索的 request ID。

环境笔记不需要写成一键安装大全；能让人从零复现、出问题时知道先看哪一层，就已经达到目的。
