这组笔记基于 [EasyVibe](https://github.com/DatawhaleChina/easy-vibe) 附录第一章至第九章重写，核对范围是九章中的 104 个 Markdown 文件。目标不是复刻一套计算机课程，而是建立 AI 研发工程师需要的工作地图：能看懂一个 Agent 或模型服务运行在哪里、数据怎样流动、失败从哪里开始，以及上线前拿什么证明它可用。

## 我做了什么取舍

- 第一章只保留一页，知道问题该往硬件、操作系统、网络、数据结构和语言中的哪一层找即可。
- 开发工具、浏览器、后端和运维章节合并了重复命令、产品介绍和交互演示，只留下判断方法。
- 数据与架构章节补上 AI 服务常见的 trace、评测集、预算、限流和权限边界。
- AI 章节是重点：模型原理、RAG、上下文、Agent、协议、部署和评测放在完整链路里讲。
- 工程素养章节保留代码质量、测试、安全、许可和交付，因为这些决定 AI 项目能否长期维护。
- 原有动画和交互教学改成静态表格、ASCII 流程图和短示例，方便搜索、复习和快速定位。

## 怎么读更省时间

| 当前目标 | 先读 |
| --- | --- |
| 本地跑 Agent、排查环境问题 | 第 1、2、3、4 章中与当前链路有关的页面 |
| 做一个聊天或文档问答应用 | 浏览器前端、RAG 与 Agent、模型生命周期 |
| 把服务部署到公网 | 后端、数据、架构、基础设施和可观测性 |
| 做多租户或企业级服务 | 数据库、系统设计、安全与交付 |
| 参与模型或 Agent 平台研发 | 第 8 章三页全部，再补数据与架构 |

不必按顺序全部读完。每一页都尽量回答三个问题：

1. **它在哪里发生？** 浏览器、本机进程、容器、控制面，还是远端模型服务。
2. **输入和输出是什么？** 失败会以什么形式出现，超时和重试由谁负责。
3. **证据是什么？** 日志、状态码、trace、指标、文件或评测结果，哪个能证明结论。
