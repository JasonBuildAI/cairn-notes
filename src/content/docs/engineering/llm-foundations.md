这一页不追求把 AI 做成专业课，而是建立能解释实际问题的模型：为什么 token 很贵、为什么上下文会丢、为什么模型会自信地编造，以及多模态系统到底接了什么。

## 1. AI 主线只需记住几个阶段

| 阶段 | 核心想法 | 留下的经验 |
| --- | --- | --- |
| 符号主义 | 把知识写成规则，让机器推理 | 规则可解释，但难以覆盖真实世界的模糊性 |
| 专家系统 | 把专家经验编码成规则库 | 维护成本高，遇到规则外情况就失效 |
| 统计机器学习 | 从数据中学习边界 | 特征和泛化开始取代手写规则 |
| 深度学习 | 多层网络自动学习表示 | 数据和算力成为关键，反向传播复兴 |
| Transformer | 用注意力并行处理序列 | 长距离依赖、规模化训练和大模型成为可能 |
| 生成式大模型 | 预训练 + 指令微调 + 对齐 | 一个模型可迁移到许多语言任务，但仍不是知识库 |

这不是一条“旧方法全部淘汰”的直线。规则、检索、分类器、小模型和大模型经常组合使用。技术选择要看任务是否需要确定性、实时性、隐私和可解释性。

## 2. 神经网络在学什么

一个神经元接收若干输入，乘以权重、加上偏置，再经过非线性激活：

```text
输出 = 激活(
  权重₁ × 输入₁ + 权重₂ × 输入₂ + ... + 偏置
)
```

多层神经元串联后，可以表示复杂函数。训练时：

1. 前向计算得到预测；
2. 用损失函数衡量预测和目标的差距；
3. 反向传播计算每个参数对损失的梯度；
4. 用梯度下降类算法更新参数。

没有非线性，多层网络仍等价于一次线性变换，无法学习复杂模式。过拟合则是模型记住了训练样本，却没有学会泛化；需要用更多数据、正则化、早停或更合适的模型容量处理。

对 AI 研发工程师，不必手推所有梯度，但要理解：训练目标决定模型优化什么，数据分布决定模型擅长什么，推理参数不会修复训练中缺失的能力。

## 3. Transformer 的主线

```text
文本 → token → ID → embedding + 位置
     → 注意力 / 前馈 → 下一个 token 概率
```

注意力让每个位置从其他位置收集信息。Query（查询）、Key（键）和 Value（值）可以这样理解：

- Query：当前位置想找什么。
- Key：其他位置能被怎样匹配。
- Value：匹配后真正被取走的信息。

缩放点积注意力常写成：

```text
Attention(Q, K, V) = softmax(QKᵀ / √d) V
```

多头注意力并行学习不同关系，再拼接结果。残差连接、归一化和前馈层让深层网络能够稳定训练。生成式模型使用因果掩码，保证当前位置只能看到前面的 token。

位置编码告诉模型顺序。没有它，注意力像一个无序词袋。现代模型常用可学习位置、旋转位置编码或适合长上下文的方案。

## 4. Token、上下文和生成

模型不直接看字符，而是看 tokenizer 产生的 token。中文、英文、代码和数字的切分效率不同，所以字符数不等于 token 数。

自回归模型每一步预测下一个 token，再把结果接回序列。常见控制参数：

| 参数 | 作用 | 代价 |
| --- | --- | --- |
| temperature | 提高或降低随机性 | 太低重复，太高不稳定 |
| top-p / top-k | 只在候选集合中采样 | 缓解低概率胡言，不等于事实校验 |
| max tokens | 限制输出长度 | 截断可能发生在关键结论前 |
| stop / schema | 约束结束或输出结构 | 仍需运行时验证 |

上下文窗口包含系统指令、对话、检索片段、工具结果和输出预算。它既是模型工作区，也是成本和延迟来源。上下文越长，并不意味着模型会同等关注所有内容；关键信息应放在明确结构里，并用摘要、检索和选择性保留控制体积。

模型会生成“最可能的文本”，不是查询事实数据库。训练数据过时、提示缺少证据、问题本身含糊时，它可能编造。减少幻觉要靠检索证据、要求引用、结构化校验、工具查证和人工边界，而不是只加一句“不要出错”。

## 5. Embedding 与语义检索

Embedding 把文本、图片或音频映射成向量。语义相近的内容在向量空间中更接近，常见相似度是余弦相似度。

它适合“意思相近”的召回，不适合替代精确条件：

- 订单号、权限范围、日期等硬条件仍需结构化过滤。
- “相似度最高”不代表“能回答问题”，需要 rerank 和评测。
- 模型、维度和分块变了，向量通常要重建。
- embedding 可能继承训练数据偏差，也可能把敏感信息编码进去。

## 6. 多模态怎样接进语言模型

不同模态最终都要变成模型能处理的序列：

| 模态 | 常见做法 | 工程关注点 |
| --- | --- | --- |
| 图像 | 切 patch、视觉编码器、投影到语言空间 | 分辨率、OCR、表格、成本 |
| 音频 | 波形转频谱或离散 token，再交给编码器/解码器 | 采样率、噪声、说话人、延迟 |
| 语音识别 | 声学特征 → 文本 token | 热词、口音、时间戳、隐私 |
| 语音合成 | 文本 → 声学表示 → 波形 | 自然度、音色授权、流式输出 |
| 视频 | 抽帧、时序编码或音视频联合建模 | 采样策略、长视频、带宽 |
| 3D | 点云、多视角图像、隐式表示或 3D 资产 | 坐标系、尺度、格式和渲染 |
| 图像生成 | 扩散模型从噪声逐步去噪，受文本条件引导 | 版权、内容安全、可复现性 |

视觉语言模型通常由视觉编码器、跨模态投影和语言模型组成。训练先做图文对齐，再用视觉指令数据微调。图像生成和视觉理解不是同一种任务：前者产出像素，后者产出描述、标签或决策。

多模态系统不能只看“模型支持图片”。还要验证分辨率、文档版面、OCR、长视频抽帧、音频时间对齐，以及不同模态之间的错误如何传播。

### 生成链路：图像、视频与语音

图像生成通常先把文本编码成条件，再从潜空间的噪声开始逐步去噪，最后由解码器还原成像素。扩散模型关注“怎样从噪声恢复数据”，Flow Matching 等方法学习从噪声分布到数据分布的连续变换；名字不同，工程上都要记录模型版本、采样步数、分辨率、提示和随机种子。视频还多出时间维度和帧间一致性，成本远高于单张图片。

语音不是直接“把波形丢给语言模型”。识别通常先把波形变成短时频谱或梅尔特征，再由声学模型输出文本、时间戳或置信度；合成则从文本生成声学表示，再由声码器还原波形。流式语音要关心首包延迟、断句、打断和回声消除。声音克隆还必须处理授权、水印和防滥用，不能因为技术上做得到就默认可以使用。

## 7. 能力地图：什么时候该用哪类模型

| 能力族 | 典型任务 | 常用方案 |
| --- | --- | --- |
| 文本理解 | 分类、抽取、匹配、摘要 | 小模型、LLM、规则组合 |
| 文本生成 | 问答、写作、代码、结构化输出 | 生成式 LLM + 校验 |
| 视觉理解 | 分类、检测、分割、OCR、VQA | CNN/ViT、检测模型、VLM |
| 视觉生成 | 配图、修图、视频生成 | 扩散模型、条件生成 |
| 语音 | ASR、TTS、说话人识别、降噪 | 专用语音模型或统一多模态模型 |
| 时序与结构化 | 预测、异常检测、Text-to-SQL | 统计模型、时序模型、LLM + 工具 |
| 检索与知识 | RAG、知识图谱、向量检索 | embedding、混合检索、图查询 |
| Agent | 工具调用、规划、工作流自动化 | LLM + 工具 + 状态机 + 沙箱 |
| 科学与工程 | 分子、蛋白、材料、仿真 | 领域模型、PINN、专用数据管线 |

能力词典可以列得很长，但研发决策通常只问四件事：任务是否需要生成、是否需要精确、错误成本多高、有没有可验证的反馈信号。

## 8. 一页检查表

1. 任务是预测、检索、生成还是行动？真的需要 LLM 吗？
2. token 预算、上下文长度和输出上限是多少？
3. 事实来自模型参数、检索证据还是工具查询？
4. 多模态输入的格式、尺寸、采样和失败模式是否验证过？
5. 生成结果的正确性、引用、延迟和成本怎样度量？
